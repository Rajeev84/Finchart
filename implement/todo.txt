1. EXECUTIVE SUMMARY
------------------------------------------------------------------------------

  Verdict: NOT DIRECTLY COMPATIBLE.

  EasyPyChart and Finchart share the same rendering backend (Tkinter Canvas)
  and similar domain concepts (candlesticks, drawing tools, indicators, subplots),
  but their PUBLIC APIs are fundamentally incompatible at every integration
  layer:

    - Constructor signatures differ
    - Data models differ (pandas DataFrame vs. List[OHLCV])
    - Drawing creation APIs differ (direct create_* vs. DrawingState + add_drawing)
    - Coordinate systems differ (datetime+price vs. bar_index+price)
    - Color models differ (hex strings vs. Color dataclass)
    - Event systems differ (simple callback vs. TradingView-style trigger)
    - Rendering pipelines differ (immediate mode vs. retained mode)

  APPROACH: Rather than building an API bridge/shim, we implement the missing
  EasyPyChart-compatible features DIRECTLY in Finchart, preserving Finchart's
  existing modular, TradingView-style architecture. This makes Finchart
  natively support the capabilities the tkinter trading software needs:
    - Pattern search all shapes (get_area_xy / get_all_shapes)
    - Layout & session save/load (per-symbol, per-timeframe)
    - DataFrame-based data loading with datetime support
    - Hex-string color acceptance in drawing APIs

  The single most valuable EasyPyChart feature that Finchart is MISSING is the
  "pattern search all shapes" capability (get_area_xy / get_all_shapes),
  which must be IMPLEMENTED DIRECTLY in Finchart.

3. PATTERN SEARCH / ALL SHAPES FEATURE ANALYSIS
------------------------------------------------------------------------------

3.1  WHAT IS THE "PATTERN SEARCH ALL SHAPES" FEATURE?
--------------------------------------------------------

  The user described "a feature for pattern search all shapes which can be
  useful to spot particular shapes created by a tool strategy." This maps to
  EasyPyChart's ability to:
    1. Enumerate ALL drawings on the chart
    2. Extract structured coordinate data for each shape
    3. Classify shapes by type (hline, vline, line, rect, text)
    4. Use this data for pattern matching/analysis â€” e.g., a strategy
       scanning all drawn trend lines for specific angle patterns, or all
       rectangles for support/resistance zones

  This is the bridge between user-drawn annotations and programmatic strategy
  analysis â€” essential for trading software that reads back user drawings for
  automated decision-making.

3.2  EASYPYCHART IMPLEMENTATION
--------------------------------------------------------

  a) chart.drawings â€” dict of all shapes:
      {tag: {'type': str, 'points': [(dt, price), ...], 'fill': hex, 'label': str,
             'plot': str, 'width': int, 'dash': tuple|None, 'kwargs': {}}}
     - Public attribute (directly accessible)
     - Keys are string tags (e.g., 'hline_1234567', 'line_1234567')
     - Points are (Datetime, price) tuples

  b) chart.get_area_xy(tag) â€” IMPLEMENTED (core.py lines 667-738):
      Returns: {'tag': str, 'shape': str, 'coordinates': [...], ...}
      - Classifies shape type:
        - line where price1==price2 -> 'hline'
        - line where dt1==dt2       -> 'vline'
        - line otherwise            -> 'aline' (angled)
      - rectangle -> returns closed polygon [(x1,y1),(x2,y1),(x2,y2),(x1,y2)]
      - text      -> {'tag', 'shape': 'text', 'coordinates': [(dt,price)], 'text': str}
      - Returns None if tag not in drawings

  c) chart.get_all_shapes() â€” DOCUMENTED BUT NOT IMPLEMENTED:
      Documented in README_REFERENCE.rst (lines 228-236):
        "get_all_shapes() â€” Returns a list of all active shapes with their
        coordinates. Returns: [{'tag': '...', 'coordinates': ...}, ...]"
      BUT: search for "def get_all_shapes" in all .py files â†’ 0 results.
      The method is NOT implemented in core.py. It is only DOCUMENTED.

  d) list_all_shapes() â€” DEMO-ONLY helper (test_drawing_tools.py, lines 129-137):
      A manual function that iterates chart.drawings.keys() and calls
      chart.get_area_xy(tag) for each. NOT a chart method.
      This is the actual working pattern for "search all shapes" in EasyPyChart.

  CONCLUSION: EasyPyChart's "pattern search all shapes" = iterate chart.drawings
  (public dict) + call get_area_xy(tag) per shape. The get_all_shapes() method
  is aspirational documentation, not implemented code. But get_area_xy() IS
  the implemented core capability.

3.3  FINCHART IMPLEMENTATION (CURRENT STATE)
--------------------------------------------------------

  Finchart has NO equivalent feature:
    - chart._drawings â€” dict of DrawingState objects: {id: DrawingState}
      (PRIVATE, prefixed with _ â€” not part of public API)
    - chart._drawing_tools â€” dict of DrawingTool instances: {id: DrawingTool}
      (PRIVATE)
    - DrawingState has: points, tool_type, label, color, width, style, fill,
      pane_name, quantity, visible, selected, hovered, locked
    - DrawingState.to_dict() â€” serialization but coordinates are raw
      (bar_index, price) tuples, NOT datetime
    - NO get_area_xy() method on ChartWidget
    - NO get_all_shapes() method on ChartWidget
    - NO public method to enumerate drawings with structured coordinates

  To "search all shapes" in Finchart currently requires:
    for shape_id, state in chart._drawings.items():
        print(state.tool_type, state.points, state.label)
    # But this accesses private API â€” not safe for external strategy code

3.5  WHY THIS MATTERS FOR TRADING STRATEGY AUTOMATION
--------------------------------------------------------

  The "pattern search all shapes" capability is CRITICAL for porting a tkinter
  trading software because:

  1. TRADING STRATEGIES READ USER DRAWINGS: A strategy ("tool strategy") often
     needs to scan all user-drawn shapes to identify patterns â€” e.g., "find all
     horizontal support lines above current price" or "detect rectangles that
     represent trading ranges."

  2. EasyPyChart's get_area_xy() ALREADY provides structured coordinate
     extraction: it classifies shape type (hline vs. vline vs. angled line),
     converts datetime anchors to indices, and returns polygon coordinates for
     rectangles. This is exactly what a pattern-matching engine needs.

  3. Finchart's DrawingState stores points as (bar_index, price) â€” the data IS
     there, but there is NO public method to extract it in a structured,
     classified format. A strategy would have to reach into private internals.

  4. The datetime-to-bar-index conversion is needed: EasyPyChart drawings
     anchor on datetime values; Finchart drawings anchor on bar indices.
     The get_area_xy/get_all_shapes implementation should optionally convert
     bar indices back to timestamps for strategy readability.

5. RECOMMENDATIONS â€” DIRECT IMPLEMENTATION IN FINCHART
------------------------------------------------------------------------------

  Rather than building a side-by-side API bridge, implement the missing features
  directly in Finchart's existing class hierarchy. This preserves Finchart's
  modular, TradingView-style architecture while adding EasyPyChart-compatible
  capabilities. Each enhancement is a thin additive layer â€” no monkey-patching,
  no parallel codebase.

5.1  FEATURE 1: PATTERN SEARCH â€” get_area_xy() + get_all_shapes()
---------------------------------------------------------------

  Add to ChartWidget (api/widget.py):
    - get_area_xy(shape_id: str) -> dict
        Returns: {'id': str, 'tool_type': str, 'shape': str,
                  'coordinates': [(x, y), ...], 'label': str,
                  'color': str(hex), 'width': float, 'pane': str, ...}
        - Classifies shape subtype:
          * hline: all points share same price -> 'hline'
          * vline: all points share same index -> 'vline' (if supported)
          * trendline/angleline: two distinct points -> 'line'/'aline'
          * rectangle: four points -> 'rectangle' (returns closed polygon)
          * longshort: multi-point -> 'longshort'
        - Optionally converts bar_index -> timestamp via
          DataStore.get_timestamp_from_index() for human-readable output
        - Returns None if shape_id not found

    - get_all_shapes() -> list[dict]
        Iterates self._drawings, calls get_area_xy() for each.
        Returns: [{'id': str, 'tool_type': str, 'shape': str,
                   'coordinates': [...], 'label': str}, ...]
        Filters out internal/ghost shapes if needed.

    - drawings property (read-only):
        Returns a list of shape IDs (or a copy of the id->DrawingState keys)
        so external code can enumerate without touching private internals.

  Add to DrawingState (drawing/base.py):
    - to_export_dict(coord_engine=None, data_store=None) -> dict
        Returns coordinates with optional datetime/timestamp conversion.
        Compatible with EasyPyChart's get_area_xy() output format.

  Add to DrawingTool ABC (drawing/base.py):
    - get_area_xy(coord_engine, viewport) -> dict
        Abstract method: each tool extracts its own structured coordinates.

  Implement in each tool (drawing/tools.py):
    - TrendLine.get_area_xy() â€” returns line coords, classifies as hline/vline/aline
    - HorizontalLine.get_area_xy() â€” returns 'hline' with single price
    - VerticalLine.get_area_xy() â€” returns 'vline' with single index (if impl.)
    - AngleLine.get_area_xy() â€” returns 'aline' with angle info
    - Rectangle.get_area_xy() â€” returns closed 4-point polygon
    - LongShortPosition.get_area_xy() â€” returns entry/stop/target coords

  Add a SessionManager class (new file: core/session.py):

    - Manages per-symbol/timeframe view states (zoom + scroll position)
    - Manages global indicator configs (persist across symbols)
    - Manages subplot layout configs
    - save_session(filepath) / load_session(filepath) / load_symbol_session()
    - set_context(symbol, timeframe) / clear_all_drawings() /

5.7  INDICATOR INDEPENDENCE ANALYSIS (EasyPyChart vs Finchart)
---------------------------------------------------------------

  EASYPYCHART PHILOSOPHY — NO BUILT-IN INDICATORS, PURE SUBPLOT RENDERING:
  EasyPyChart does NOT ship with indicator classes (no RSI/MACD/SMA objects).
  Instead, it provides a single generic method:

    chart.create_series(plot_name, data, color, type, label, thickness)

  - 'plot_name': target subplot ('candlestick' for main, 'rsi_pane' for sub)
  - 'data': a list/Series of RAW pre-computed values (length matches OHLCV bars)
  - 'type': 'line', 'histogram', or 'area'
  - The chart only RENDERS the data — it does NOT know or care what the values
    represent. The indicator CALCULATION is done entirely by external code
    (the user's scanner/def_scanner.py module).

  Example from demo_fullfeatures.py (EasyPyChart):
    close = df["Close"]
    sma20 = close.rolling(20).mean()     # computed externally
    chart.create_series("candlestick", sma20, color="#FFCC33",
                        thickness=2, label="SMA 20")

    rsi14 = compute_rsi(close)            # computed externally in def_scanner.py
    chart.create_series("rsi", rsi14, color="#35D6A6",
                        thickness=2, label="RSI 14")

  Key points:
    - Indicators are EXTERNAL computations plotted as generic series
    - The chart has NO hardcoded indicator type checks whatsoever
    - Subplot creation (create_subplot) and series plotting (create_series)
      are fully decoupled
    - Any custom scanner/strategy can compute any indicator and plot it
    - The only "type" the chart knows is render style: 'line', 'histogram', 'area'
    - Series updates use a fluent interface: chart.plot("SMA 20").update(new_data)

  FINCHART APPROACH — BUILT-IN INDICATOR CLASSES WITH HARDCODED CHECKS:
  Finchart ships with Indicator subclasses (SMA, EMA, RSI, MACD, BollingerBands,
  Volume), each implementing calculate() + render_commands(). BUT the widget.py
  has HARDCODED checks that tie specific behavior to specific class names and
  pane names, making it impossible to add truly custom indicators without
  modifying the widget:

  HARDCODED CHECKS IN widget.py:
    1. Line 205: indicator.__class__.__name__ == "RSI"
       -> Sets PriceScale.fixed_range = True and price range to (0, 100)
       PROBLEM: Only "RSI" class gets fixed range. A custom RSI-like indicator
       with a different class name won't get its fixed range set.

    2. Line 211: indicator.__class__.__name__ == "Volume"
       -> Placeholder (no action, but the class-name check is still there)

    3. Line 707: ind.pane == "volume"
       -> Forces p_min = 0.0 (volume bars grow upward from zero)

    4. Line 716: ind.pane == "macd"
       -> Forces symmetric range around zero (max_abs = max(|min|, |max|))

    5. Line 891: pane_name == "volume"
       -> Uses M/B/K shorthand formatting for crosshair badge

  GAPS VS EASYPYCHART:
    - No create_series() method: must subclass Indicator to plot anything
    - No plot().update() fluent interface
    - Class-name checks prevent custom indicators from getting pane-specific
      scaling (fixed ranges, zero-baseline, symmetric ranges)
    - IndicatorResult only stores 'values' dict — no metadata for pane scaling

  RECOMMENDATION: Make indicators self-describing via metadata on the base class,
  so the widget reads properties GENERically instead of hardcoding class names.
  See Section 6.9 for implementation plan.
